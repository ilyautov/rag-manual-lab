## Извлечение текста

Документы приходят из разных мест: PDF, страницы внутренней вики, DOCX, выгрузки из системы заявок. Для каждого формата есть свои инструменты, и у каждого свои артефакты. Из PDF текст достают по координатам символов, поэтому колонки склеиваются, таблицы рассыпаются в строки, а колонтитулы повторяются на каждой странице. Из HTML приходят меню, подвалы и сущности вроде `&nbsp;`. DOCX сохраняет структуру лучше всех, если авторы пользовались стилями заголовков, а не жирным шрифтом.

Правило одно: после извлечения посмотрите глазами на десяток документов каждого типа. Ни одна метрика поиска не скажет вам, что половина регламентов превратилась в набор слов без пробелов.

Дальше простого чтения символов пошли извлекатели, которые понимают устройство страницы: находит заголовки, таблицы, списки и колонки и отдают текст вместе с этой разметкой. Для регламентов с таблицами сроков и сумм это меняет дело: таблица остаётся таблицей, а не рассыпается по строкам, и заголовок раздела остаётся при своём тексте. Инструментов такого рода несколько открытых проектов, и выбирают их так же, как очистку: проверкой на десятке живых документов. В лаборатории исходники уже структурные, поэтому шаг показан словами, без кода.


## Очистка

В лаборатории очистка делает четыре вещи. Убирает HTML-сущности, склеивает переносы на конце строки, выбрасывает колонтитулы и схлопывает пробелы.

```ts
export function cleanText(raw: string, boiler: Set<string>): string {
  return raw
    .replace(/&nbsp;/g, ' ')
    .replace(/(\p{L})-\n(\p{L})/gu, '$1$2')
    .split('\n')
    .map((l) => l.trim())
    .filter((l) => l && !boiler.has(l) && !PAGE_LINE.test(l))
    .map((l) => l.replace(/[ \t]+/g, ' '))
    .join('\n');
}
```

Колонтитулы находятся без ручного списка: строка, которая встречается в трёх и более документах и не служит заголовком, почти наверняка служебная. В нашем корпусе так нашлось {{corpus.boiler}} строки: шапка регламента и пометка о конфиденциальности. Номер страницы в шапке меняется, поэтому для него есть отдельное правило `PAGE_LINE`: короткая строка, которая кончается на «стр. N». Учебная выгрузка из PDF после очистки сократилась с {{corpus.sampleRaw}} до {{corpus.sampleClean}} символов, и всё сокращение пришлось на мусор: текст правила сохранился целиком, а «ненадлежащего ка-чества» снова стало одним словом.

::: {.warn data-title="Типичная ошибка"}
Склеивать переносы, не думая о дефисах. Правило выше превратит «бело-» в конце строки и «розовый» в начале следующей в «белорозовый»: оно не отличает перенос от настоящего дефиса, который случайно оказался на краю строки. Для поиска такая ошибка почти безвредна, а в цитате заметна. Если исходник позволяет, берите текст из источника без вёрстки: из вики, а не из её PDF-копии.
:::

## Структура

Регламент состоит из разделов, и раздел обычно отвечает на один вопрос: «Срок заявления», «Возврат денег», «Что нужно от покупателя». Структуру стоит сохранить при извлечении, потому что она пригодится трижды: для нарезки на фрагменты (глава 3), для заголовка, который добавляют к каждому фрагменту, и для ссылки в ответе («раздел „Срок заявления“»). Лаборатория разбирает документ по строкам `## Заголовок` и хранит список разделов рядом с текстом.

## Метаданные

К каждому документу после подготовки прикреплены поля, без которых нельзя сделать половину следующих глав.

| Поле | Пример | Зачем |
|---------------------|-------------------|---------------------------------------------|
| `id` | `ret-defect-v2` | ссылка в ответе, тесты, удаление |
| `group` | `ret-defect` | версии одного правила связаны группой |
| `version` | `2` | выбор действующей версии |
| `validFrom`, `validUntil` | `2025-09-01` | дата вступления в силу и окончания (глава 9) |
| `access` | `all` или `senior` | фильтр по правам до поиска (глава 9) |
| `source` | `wiki/returns/defect` | откуда пришёл документ, кому писать об ошибке |
| `injectionFlag` | `true` | подозрение на инструкцию внутри текста (глава 12) |

Метаданные почти никогда не лежат в самом тексте. Дату вступления в силу знает юрист, права знает руководитель поддержки, источник знает система, из которой выгружен файл. Поэтому подготовка документов означает ещё и договорённость: кто и где заполняет эти поля. Документ без даты и без прав лучше не индексировать вовсе, чем индексировать с правами «для всех» по умолчанию.

## Дубликаты

Один и тот же регламент часто живёт в двух местах: в новой вики и в старой базе знаний, откуда его когда-то скопировали. Дубликаты вредны дважды. Они занимают места в выдаче поиска, вытесняя другие полезные фрагменты, и они расходятся со временем: оригинал поправили, копию забыли.

Лаборатория ищет почти-дубликаты по шинглам, перекрывающимся тройкам слов. Для двух документов считается коэффициент Жаккара, доля общих шинглов среди всех.

::: formula
::: f
J(A, B) = |A ∩ B| / |A ∪ B|
:::
Если J не меньше 0,8, второй документ считается копией первого и в индекс не попадает. Порог подбирают по своим данным, глядя на пары около границы.
:::

Копия регламента возврата из старой базы знаний совпала с оригиналом полностью: J = {{corpus.dupJaccard}}, и после подготовки из {{corpus.rawDocs}} документов осталось {{corpus.docs}}. Две версии регламента о браке, наоборот, похожи лишь на {{corpus.versionJaccard}}: их нельзя схлопывать как дубликаты, это разные правила, и выбирать между ними будет фильтр по дате.

::: {.note data-title="Коротко"}
Подготовка документов сводится к трём вопросам: читается ли текст человеком, сохранена ли структура и заполнены ли поля версии, даты, прав и источника. Дубликаты удаляют до индексации, версии оставляют и различают метаданными.
:::

## Чек-лист подготовки

1. Для каждого формата посмотрите глазами на 10 извлечённых документов.
2. Найдите колонтитулы по частоте строк, а не списком вручную.
3. Сохраните заголовки разделов.
4. Заполните `version`, `validFrom`, `access`, `source`; без них документ не индексируется.
5. Удалите почти-дубликаты и проверьте пары около порога глазами.
6. Пометьте подозрительные фразы, обращённые к ассистенту (подробнее в главе 12).

::: {.lab data-title="Лаборатория"}
`npm run prepare:demo` печатает найденные колонтитулы, пару дубликатов с коэффициентом Жаккара и очищенную выгрузку из PDF. Тесты «очистка выгрузки…» и «версии одного регламента не считаются дубликатами» в `test/prepare.test.ts` проверяют {{corpus.sampleRaw}} → {{corpus.sampleClean}} символов и то, что версии не схлопнулись.
:::

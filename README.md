# RAG: поиск, контекст, ответ

Бесплатная книга на русском о том, как построить помощника, который отвечает по базе документов, ссылается на источник и честно отказывается, когда ответа нет. С воспроизводимой лабораторией на TypeScript.

Третья книга серии после [«Теории LLM и практики AI-лаборатории»](https://github.com/ilyautov/llm-manual-lab). Там RAG занимал одну главу, здесь он разобран от сырого документа до оценки ответа.

## Для кого

- **Инженерам**, которые строят поиск по документам с генерацией ответа и хотят понимать, на каком шаге что ломается.
- **Руководителям**, которые ставят такие задачи: когда RAG нужен, как устроены права и свежесть, как отличить ошибку поиска от ошибки модели. Главы с пометкой «для всех» читаются без формул.

Сквозной пример: внутренний помощник поддержки выдуманного интернет-магазина «Полка» отвечает операторам по базе регламентов. «Сколько дней у покупателя на возврат товара ненадлежащего качества?», «Можно ли вернуть уценённый товар?». Регламенты, сроки и суммы придуманы и не описывают действующее законодательство.

## Быстрый старт

Нужен Node.js 24. Внешних пакетов и сети не нужно.

```bash
npm test                                   # 49 тестов: ключевые числа книги
npm run ask -- "можно ли вернуть уценённый товар"
npm run ask -- "сколько бонусов может начислить старший смены" --senior
```

## Лаборатория

```bash
npm run prepare:demo  # глава 2: очистка, колонтитулы, дубликаты
npm run chunk         # глава 3: размер фрагмента
npm run bm25          # глава 4: BM25 руками
npm run vector        # глава 5: косинус
npm run hybrid        # глава 6: BM25, вектор, RRF, min-max
npm run rerank        # глава 7: MMR и бюджет
npm run answer        # глава 8: проверка опоры и порог отказа
npm run access        # глава 9: права и версии
npm run eval          # глава 10: метрики и bootstrap
npm run judge         # глава 11: каппа и разложение сбоев
npm run prod          # глава 12: переиндексация, кеш, внедрённые инструкции
npm run numbers       # пересчитать build/numbers.json
npm run build         # собрать PDF (нужны pandoc, pdftotext, pdffonts, Google Chrome)
```

Корпус лежит в `src/corpus.ts`, тестовый набор в `src/questions.ts`, все опыты книги в `src/experiments.ts`.

### Что моделируется честно, а что нет

| Часть | Что работает по-настоящему | Граница вывода |
|---|---|---|
| `bm25.ts` | BM25 и TF-IDF по формулам | нормализация русского грубая, обрезка окончаний |
| `embed.ts` | косинус, нормировка, полный перебор | эмбеддинги игрушечные: хеш символьных 3-грамм, не нейросеть |
| `rerank.ts` | двухэтапный поиск, MMR | реранкер детерминированный, не cross-encoder |
| `answer.ts` | проверка опоры и отказ | ответ собирает шаблон, LLM не вызывается |
| `judge.ts` | каппа Коэна | судья детерминированный, метки человека поставлены автором |
| `prod.ts` | хеши, кеш, карантин | журнал запросов синтетический |

Выводы о сравнении методов сделаны на маленьком учебном корпусе и переносятся на ваши данные только как гипотеза.

## Сборка PDF

`node build/build.mjs` из корня проекта: Markdown глав из `chapters/` → pandoc → HTML → PDF через headless Chrome. Числа подставляются из `build/numbers.json`, сборка падает на отсутствующем ключе. Результат: `out/RAG_поиск_контекст_ответ.pdf`.

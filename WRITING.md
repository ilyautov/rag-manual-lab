# Правила для книг серии (агенты, RAG)

Серия продолжает «Теорию LLM и практику AI-лаборатории» (github.com/ilyautov/llm-manual-lab). Читатель: инженер, который встраивает LLM в продукт, и руководитель, ставящий такие задачи. Тон: спокойный, практический, на примерах. Формулы допустимы, но смысл всегда объяснён словами.

## Главный принцип

Каждое число в тексте получено кодом лаборатории. В Markdown число пишется как `{{ключ}}`, значение кладёт `scripts/numbers.ts` в `build/numbers.json`. Сборка падает на отсутствующем ключе. Руками число не вписывается (исключения: номера глав, годы, константы определения вроде «20 шагов», «k = 5», входные параметры примера, которые сами задают задачу; их можно писать текстом, но лучше тоже брать из numbers).

Десятичный разделитель в тексте запятая: `numbers.ts` форматирует строки сам (`0,36`, `36 %` пишем как `36%`).

## Язык (обязательные запреты)

- Никаких тире «—» и «–» (кроме числовых диапазонов «2–5»). Вместо них запятая, двоеточие, точка, скобки или перестройка. «X — это Y» заменяй на «X называют Y», «X служит для», «X означает».
- Не использовать: «не просто X, а Y», «не только X, но и Y», «является», «стоит отметить», «важно понимать/отметить», «данный/данная», «играет ключевую роль», «в современном мире», «таким образом» в начале вывода, «подводя итог», «погрузимся», «раскрыть потенциал», «комплексный подход», «в связи с этим».
- Канцелярит на глаголы: «осуществить проверку» → «проверить».
- Без эмодзи, без восклицательных знаков в основном тексте.
- Термины на английском в первый раз даются с русским пояснением, дальше как удобно (tool call, retrieval, chunk).
- Кавычки-ёлочки «» в тексте, прямые в коде.

## Разметка глав

Один файл на главу: `chapters/NN-slug.md`. В главе ровно один заголовок первого уровня с кикером:

```
# Название главы {data-kicker="ГЛАВА 3 / ДЛЯ ВСЕХ"}
```

Кикер: `ГЛАВА N / ДЛЯ ВСЕХ` или `ГЛАВА N / ДЛЯ ИНЖЕНЕРОВ`. Введение: `ВВЕДЕНИЕ`, приложения `ПРИЛОЖЕНИЕ А`. Дальше `##` и `###`.

Первый абзац главы оформляется как лид: `::: lead` … `:::`.

Блоки (pandoc fenced divs):

- `::: {.note title="Коротко"}` голубая врезка: суть, определение.
- `::: {.warn title="Типичная ошибка"}` янтарная: заблуждение и чем оно кончается.
- `::: {.lab title="Лаборатория"}` лаймовая: какая команда, что печатает, что проверяет тест.
- `::: {.check title="Проверьте себя"}` вопросы в конце главы (ответы в приложении).
- `::: {.flow title="..."}` тёмная панель: внутри нумерованный список из 3–5 шагов, у каждого `**Заголовок**` и строка пояснения. Пример:

```
::: {.flow title="Цикл агента"}
1. **План** выбрать следующий шаг
2. **Действие** один вызов инструмента
3. **Проверка** сверить результат с целью
4. **Итог** ответ или новый шаг
:::
```

- `::: formula` белая рамка; строка формулы абзацем с классом: `[p^n = 0,95^20 ≈ {{rel.p95}}]{.f}` не работает для блока, поэтому пиши так:

```
::: formula
::: f
P(успех) = p^n
:::
Пояснение под формулой.
:::
```

  (во вложенном div класс `f` оформляется моноширинным по центру; если не выходит, просто код-блок).
- Таблицы pipe-формата; первая колонка выделяется жирным автоматически.
- Код: ```` ```ts ````, короткие фрагменты (до 20 строк), полностью совпадающие с кодом в `src/` по смыслу.
- Схемы: inline `<figure><svg viewBox="0 0 680 220">…</svg><figcaption>…</figcaption></figure>`. Цвета только из палитры: фон #F6F4EE, тёмный #1F2724, лайм #B5DD4C, голубой #A8DDE1, янтарный #F4C77D, серый #D9DBD3, текст #2B302D. Шрифт в svg: `font-family="Book Sans"`, размер 11–13. Не больше 1–2 схем на главу, и только там, где схема правда объясняет механизм.

## Объём и структура

10–13 глав плюс приложения (ответы к задачам, первоисточники). Глава 3–6 страниц A4 (это примерно 900–2000 слов). Итог книги 45–70 страниц.

Каждая глава:
1. лид с бытовым или рабочим примером (сквозной сюжет книги);
2. механизм словами;
3. расчёт или трасса, числа из лаборатории;
4. типичная ошибка;
5. что сделать на практике (чек-лист, таблица решений);
6. врезка «Лаборатория» с командой `npm run …` или `npm test`;
7. «Проверьте себя» 2–4 вопроса.

## Первоисточники

Только реальные работы, которые ты знаешь точно (arXiv-номер, DOI, официальный блог/документация). Не выдумывай авторов и номера. Если не уверен, не ссылайся. Ссылки в тексте в квадратных скобках [N], список в приложении в `::: refs`.

## Лаборатория

- TypeScript, Node 24 с нативным снятием типов (`node file.ts`), без зависимостей, без `enum`, `namespace` и параметров-свойств конструктора (их type stripping не поддерживает). Импорты с расширением `.ts`.
- `package.json`: `"type": "module"`, скрипты `test` (`node --test test/`), `numbers` (`node scripts/numbers.ts`), `build` (`node build/build.mjs`), плюс демо-скрипты по главам.
- Детерминированность: никакого `Math.random()` без сида; используй свой PRNG (mulberry32) с фиксированным сидом. Никакого реального LLM в тестах: модель заменяется сценарием или детерминированным заглушечным «планировщиком».
- Тесты проверяют те же числа, которые попадают в книгу.
